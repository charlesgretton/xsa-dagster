# Evidence

The derived record behind every number in the results of the proceedings. The raw per-run
results (Dagster logs and solutions for 206 runs, about 540 MB compressed) are not distributed;
their SHA-256 is in `checksums.txt`, and they can be regenerated by rerunning the campaign with
the scripts in `hpc/` (timings will differ with the machine).

| path | what it is |
|---|---|
| `derived/runs.csv` | one record per submitted run (206), including the 3 censored runs: status, time, expanded Dagster arguments (recorded, or inferred for the 26 earliest runs), build directory, verification message, predicted subtree acceptance, observed failed subtrees |
| `derived/inventory.csv` | per batch job: runs, verified successes, timeouts, launch failures, invalid models |
| `derived/scaling.csv` | per configuration: min / median / max time, speedup, efficiency, solve-phase speedup and efficiency, worker- and allocated-core-second ratios |
| `derived/phase_breakdown.csv` | per logged run: start-up, splitter, subtree phase, join, collector |
| `derived/latency.csv` | per logged run: job compute, lag and response percentiles, utilisation |
| `derived/master_load.csv` | per logged run: master busy fraction, splitter-duplicate counts and cost |
| `derived/MANIFEST.json` | run and status counts, Dagster arguments, build directories |
| `validation/collector_disjointness.txt` | all 55 executed top-down DAGs: acyclic, single sink, variable-disjoint collector inputs |
| `validation/dag_check_against_cnf.txt` | the 10 executed DAGs at N = 2048 and 4096 checked against their CNFs |
| `validation/executed_dag_sha256.txt` | SHA-256 of all 69 executed DAG files |
| `checksums.txt` | raw results, generator, all four instances, Dagster binary |
| `provenance.txt` | compiler, libraries, MPI, OS and node configuration of the campaign |

## Regenerating the tables from raw results

From the repository root, with a directory `results/` holding one sub-directory per batch job
(each with `families.jsonl` and `runs/`), as written by the job scripts in `hpc/`:

    python3 evidence/scripts/derive.py results rederived
    diff -r evidence/derived rederived          # identical for the campaign's raw results
    python3 evidence/scripts/check_collector.py $(find results -name '*topdown*.dag')

For a new campaign the tables are regenerated in the same form; the numbers will be those of
the new machine. `derive.py` needs only the Python standard library and parses every logged
run, which takes a few minutes.
